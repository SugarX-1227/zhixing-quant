## 0. 你需要知道的第一件事：怎么拿到真实行情数据

这是过去几轮最大的瓶颈。现在解决了，**但需要你主动做一步**：

```bash
python scripts/fetch_slice.py --tag data-20260918-all   # 全量 5213 只，160MB
# 或轻量版，迭代快：
python scripts/fetch_slice.py --tag data-20260918-2     # 800 只，26MB
```

数据落到 `data/market.db`，之后扫描 / 回测 / 因子检验 / 消融 / 参数校准全都能直接跑。

可用的 release：

| tag | 内容 |
|---|---|
| `data-20260918-all` | **5213 只**（含指数）× 2021-06-01~2026-09-17，626 万根 K 线，160MB |
| `data-20260918-2` | 800 只 × 2022-01-04~2026-09-17，26MB |
| `data-20260918` | 800 只，23MB（最早那版） |

**工作流：快速试参数用 800 只的小切片，出结论前换全量复核一遍。**
5213 只跑回测明显更慢（指标流水线是逐只算的）。

⚠️ **不要试图用 MCP 连数据机器。** 仓库里有 `zhixing_quant/mcp_server.py`，
在局域网内是好用的，但云端会话物理上连不通，已实测：

- `10.9.2.237` 是 RFC1918 私有地址，云端容器无路由；且 `10.0.0.0/8` 在代理
  noProxy 名单里，会被当直连尝试 → 超时
- 架公网隧道（Cloudflare / ngrok）也不行，网关对 CONNECT 直接回 **403**，
  出网是白名单

不是配置问题，别再花时间试。GitHub 是唯一通的路。

## 4. 最该优先解决的问题

**B2 在 2022-08~2025-03 这段怎么调都是亏的**（−23% 到 −38%），2025-04 之后才转正。
出场规则最多值 ±26 个点，而基线亏 28 个点、超额亏 34 个点 ——
**问题在入场信号或择时，不在出场。** 继续调出场规则是在错的地方使劲。

两个具体怀疑方向：

1. **择时闸门可能过于敏感**：4 年里判了 525 天空头 / 478 天多头，空头占一半以上。
   OAMV 的阈值（`timing.active_value`：单日 −2.3% 转空 / +4% 转多）值得单独查。
2. **B2 入场条件**：当前实现的是通达信原始公式（`EXIST(J<13,3)` + 涨幅>3.95% +
   放量 + J<55）。规划书 4.3.1 还要求"在 B1 之后 5 日内"和"无长上下影"，
   都没实现。这两条是**收紧**入场，可能正是缺的东西。

## 6. 这个项目反复栽过的坑（务必读 AGENTS.md）

- **配置静默失效**：重复键、枚举写错、哑开关。现在有 `config_schema.py` 拦着，
  但新加配置段时记得同步更新校验。
- **回测和实盘劈成两套系统**：这个坑我自己都又踩了一次 ——
  加因子层时只接了实盘扫描器，回测引擎还在按成交额排序，
  导致改因子权重跑回测结果一个字节都不变。**加任何新规则前先问：回测里能验证吗？**
- **判据算的不是它声称的东西**：砖型图曾拿两个水平值相比（应比两个增量），
  信号量从每年数百次掉到 2.8 年 1 次；MACD 顶背离曾拿窗口最低点当"前高"。
  **改完判据一定要统计触发频率，和文档预期的量级对一下。**
- **测试全绿不等于对**：上面几个 bug 当时测试都是绿的，因为测试锁的就是错的那版。
