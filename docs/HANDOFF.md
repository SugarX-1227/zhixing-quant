## 0. 你需要知道的第一件事：怎么拿到真实行情数据

这是过去几轮最大的瓶颈。现在解决了，**但需要你主动做一步**：

```bash
python scripts/fetch_slice.py --tag data-20260918-all   # 全量 5213 只，160MB
# 或轻量版，迭代快：
python scripts/fetch_slice.py --tag data-20260918-2     # 800 只，26MB
```

数据落到 `data/market.db`，之后扫描 / 回测 / 因子检验 / 消融 / 参数校准全都能直接跑。

可用的 release：

| tag | 内容 |
|---|---|
| `data-20260918-all` | **5213 只**（含指数）× 2021-06-01~2026-09-17，626 万根 K 线，160MB |
| `data-20260918-2` | 800 只 × 2022-01-04~2026-09-17，26MB |
| `data-20260918` | 800 只，23MB（最早那版） |

**工作流：小切片只用来验代码跑不跑得通，任何结论都必须在全量上重跑。**
切片是按 2026-09 的成交额降序取前 N 只（`export_slice.py:120`），带严重
选择偏差——同一份代码同一段时间，切片上 B2 是 +115.3%，全量上是 −28.0%。
5213 只跑一次全段约 5 分钟，样本内外四个变体约 33 分钟（指标流水线逐只算）。

⚠️ **不要试图用 MCP 连数据机器。** 仓库里有 `zhixing_quant/mcp_server.py`，
在局域网内是好用的，但云端会话物理上连不通，已实测：

- `10.9.2.237` 是 RFC1918 私有地址，云端容器无路由；且 `10.0.0.0/8` 在代理
  noProxy 名单里，会被当直连尝试 → 超时
- 架公网隧道（Cloudflare / ngrok）也不行，网关对 CONNECT 直接回 **403**，
  出网是白名单

不是配置问题，别再花时间试。GitHub 是唯一通的路。

## 2. 这套系统现在有什么

在原有的「数据层 / 指标 / 扫描器 / 回测引擎 / Web 界面」之上，最近几轮加了：

| 模块 | 作用 |
|---|---|
| `backtest/exits.py` | 出场规则层。止损 / 移动止损 / 分批止盈 / 时间止损 / 防守阶梯，全部配置驱动，**回测与实盘共用** |
| `portfolio/sizer.py` | 建仓规则（底仓 + 分批加仓）、单票上限、择时仓位上限，两边共用 |
| `factors/` | 因子层：注册表 / 16 个内置因子 / 横截面打分 / IC·ICIR·分层收益 / 稳定性筛选 |
| `backtest/ablation.py` | 出场规则消融：逐条关掉看边际贡献，识别"从未触发的死规则" |
| `backtest/calibrate.py` | 参数校准：样本内外切分 / 网格扫描 / 滚动前进 / 参数平坦度 |
| `config_schema.py` | 配置校验：重复键 / 枚举写错 / 哑开关 / 未注册因子，加载时直接拦 |
| `scripts/export_slice.py`<br>`scripts/fetch_slice.py` | 行情切片导出 / 下载（走 GitHub Release） |

Web 界面 8 页：今日 / 持仓 / 战法 / 回测 / 校准 / 因子 / 个股 / 数据。

## 4. 最该优先解决的问题（2026-09-20 用全量 5213 只复核过）

**⚠️ 先看这条：`data-20260918-*` 这三个切片都有严重的选择偏差，不能用来下结论。**
`scripts/export_slice.py:120` 的选法是
`WHERE trade_date = <近期某日> AND amount >= ? ORDER BY amount DESC LIMIT ?`——
按 **2026-09 的成交额**降序取前 N 只，再拿去回测 2022 年。能在 2026 年挤进
成交额前 800 的股票，本身就是这四年跑赢的那批。实测同一份代码、同一段时间：

| 数据 | 建池 | 总收益 | 超额(沪深300) |
|---|---|---|---|
| 800 只切片 | 665 | **+115.3%** | +108.8% |
| 全量 5213 只 | 4568 | **−28.0%** | **−34.5%** |

**以全量为准。** 切片只能用来快速试代码通不通，不能用来判断策略好坏。
§3 里那些在 800 只切片上得出的结论（出场规则消融、因子稳定性）
**都需要在全量上重跑一遍**，目前状态是"未复核"。

**B2 在样本内（2022-08~2025-06）是亏的**，全量实测：

    全段    总收益 −28.0%  年化 −7.9%  最大回撤 46.8%  夏普 −0.53
            胜率 44.0%  盈亏比 2.67  成交 495 笔（涉及 319 只标的）
    样本内  −33.9%（363 笔）    样本外  +9.7%（134 笔）

这和这一节原来写的判断一致。下面三条是已经查完、**不要重做**的：

**① 择时闸门没有过敏，不要动 `timing.active_value` 的阈值。**
18 段空头（≥10 日）里 17 段活跃市值自身在跌，幅度 −5% ~ −28%，
唯一上涨的一段只有 +2.2%。最长的 79 天空头（2025-09-04~2025-12-31）
期间 OAMV −16.0%，躲对了。这个结论只依赖 OAMV 序列，与股票池无关。
另外 regime 是**锁存持续态**，NEUTRAL 只存在于历史首次触发之前，
所以长跨度回测必然 0 天中性——不是异常，但 `portfolio.neutral_max_total`
因此永远走不到，是死配置。

**② 规划书 4.3.1 的入场收紧条件帮不上忙。** 已实现为可选开关
（`b2.b1_within_days` / `b2.body_ratio_min`，默认关）。全量实测：

| 方案 | 样本内 | 样本外 | 样本内笔数 | 样本外笔数 |
|---|---|---|---|---|
| A 基线（通达信原口径） | −33.9% | +9.7% | 363 | 134 |
| B 紧跟 B1（前 5 日内） | −49.1% | +9.3% | 374 | 126 |
| C B1 + 实体≥0.6 | −43.1% | −2.3% | 349 | 133 |
| D 只加实体≥0.6 | **−31.0%** | **+17.8%** | 380 | 146 |

B、C 明显更差。D（只要求实体占全幅 ≥0.6）在全量上样本内外都略好于基线，
但在 800 只切片上样本内外都**更差**——两份数据结论相反，证据冲突，
所以默认仍是关闭。要用它得先拿第三份证据。

**③「钩明显上翘」是哑开关，没有实现。** 原公式已要求当日涨幅 > 3.95%，
14380 个 B2 信号里 99.5% 自动满足 J 上行，加上它回测逐位相同。
要实现得换更严的口径（比如要求 J 从 ≤14 的低点拐头）。

**④ 交易笔数有容量上限，扩大股票池改变不了它。**
478 个多头交易日 ÷ 平均持仓 6.6 个交易日 × 5 个槽位 ≈ 500 笔。
665 只池和 4568 只池都是 495 笔，变的是选中哪些标的（后者涉及 319 只），
不是笔数。所以「多给候选」不是提高收益的路径，**提高每笔的期望值才是**。

**还没查的方向**：B2 入场信号本身（不是规划书那几条修饰，是
`EXIST(J<13,3)` + 涨幅>3.95% + 放量 + J<55 这组判据在全市场上的区分度），
以及因子排序在全量上是否还有效（§3 的因子结论是切片上得出的）。

## 6. 这个项目反复栽过的坑（务必读 AGENTS.md）

- **配置静默失效**：重复键、枚举写错、哑开关。现在有 `config_schema.py` 拦着，
  但新加配置段时记得同步更新校验。
- **回测和实盘劈成两套系统**：这个坑我自己都又踩了一次 ——
  加因子层时只接了实盘扫描器，回测引擎还在按成交额排序，
  导致改因子权重跑回测结果一个字节都不变。**加任何新规则前先问：回测里能验证吗？**
- **判据算的不是它声称的东西**：砖型图曾拿两个水平值相比（应比两个增量），
  信号量从每年数百次掉到 2.8 年 1 次；MACD 顶背离曾拿窗口最低点当"前高"。
  **改完判据一定要统计触发频率，和文档预期的量级对一下。**
- **测试全绿不等于对**：上面几个 bug 当时测试都是绿的，因为测试锁的就是错的那版。
